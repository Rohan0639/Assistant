  MODULE DETAILS

  [1] core/preprocessor.py  (NEW)
  --------------------------------
  What it is:
    A text rewriting module. Runs AFTER Input Handler, BEFORE Intent Parser.
    Converts informal/natural language into forms the parser already knows.

  Three transformations (applied in order):

    STEP 1 -- Strip Greeting / Assistant Name Prefix
    -------------------------------------------------
    Removes words like "hey jarvis", "ok jarvis", "hey", "hi" from start.
    Patterns matched at the START of the string only.

    Supported greetings:
      hey jarvis, ok jarvis, okay jarvis, jarvis, hey there, hey, hi, hello, yo

    Examples:
      "hey jarvis play kesariya"   -> "play kesariya"
      "hi search python"           -> "search python"
      "jarvis open notepad"        -> "open notepad"

    Works correctly: YES
    Tested:         YES


    STEP 2 -- Expand Contractions and Informal Words
    -------------------------------------------------
    Replaces informal shorthand with formal equivalents.
    Replacement happens ANYWHERE in the string (not just the start).
    Longer phrases are checked before shorter ones to avoid partial matches.

    Key mappings (selected):
      wanna hear    -> want to hear
      wanna play    -> want to play
      wanna         -> want to
      lemme         -> let me
      pull up       -> go to        (routes to OPEN_WEBSITE, not OPEN_APP)
      fire up       -> launch
      boot up       -> launch
      show me       -> find
      head to       -> go to
      i'd like to   -> i would like to

    Examples:
      "wanna hear kesariya"     -> "want to hear kesariya"
      "fire up chrome"          -> "launch chrome"
      "pull up youtube"         -> "go to youtube"
      "show me python docs"     -> "find python docs"

    Works correctly: YES
    Tested:         YES


    STEP 3 -- Strip Polite Command Prefix
    --------------------------------------
    Removes polite phrases from the START of the string.
    Only one prefix is stripped to avoid over-removal.

    Supported prefixes (longest first):
      could you please, would you please, can you please, will you please,
      could you kindly, would you kindly,
      could you, would you, will you, can you,
      please, kindly

    Examples:
      "could you please open chrome"  -> "open chrome"
      "can you play kesariya"         -> "play kesariya"
      "please search python"          -> "search python"

    Works correctly: YES
    Tested:         YES

  [3] core/entity_extractor.py  (UPDATED)
  -----------------------------------------
  What changed (Phase 2):
    Added descriptor pattern stripping.
    Split filler stripping into left-only and right-only functions.
    Fixed extraction order: left fillers -> descriptor -> right fillers.

  NEW: Descriptor Pattern Stripping
    Strips "TYPE called/named VALUE" patterns, returning just VALUE.

    Pattern matches at start of remainder (after trigger is removed):
      song called X     -> X
      track named X     -> X
      app called X      -> X
      application named X -> X
      website called X  -> X
      something called X -> X

    Examples:
      "play a song called kesariya"
        trigger="play a", remainder="song called kesariya"
        -> descriptor strips "song called" -> "kesariya"
        -> entity: { song_name: "kesariya" }

      "open an app called notepad"
        trigger="open", remainder="an app called notepad"
        -> left filler strips "an" -> "app called notepad"
        -> descriptor strips "app called" -> "notepad"
        -> entity: { app_name: "notepad" }

  FIXED: Extraction Order
    Before: trigger -> descriptor -> fillers  (descriptor failed after "an")
    After:  trigger -> LEFT fillers -> descriptor -> RIGHT fillers  (correct)

  Works correctly: YES
  Tests passed:   20/20 (5 Phase 1 + 15 Phase 2)


  [4] actions/apps.py  (UPDATED)
  --------------------------------
  What changed (Phase 2):
    Added 4-tier fuzzy lookup so partial/misspelled app names still work.
    Added _is_available() helper to check both absolute paths and PATH.

  4-Tier Fuzzy Lookup (in priority order):

    Tier 1 -- Exact Match
      "chrome" in registry? Yes -> chrome.exe
      Fastest path, used for all exact inputs.

    Tier 2 -- Starts-With Match
      Any registry key starts with the user input?
      "chrom" -> "chrome" starts with "chrom" -> chrome.exe
      "calcu" -> "calculator" starts with "calcu" -> calc.exe
      "power" -> "powershell" starts with "power" -> powershell.exe

    Tier 3 -- Input Contained In Key
      User input is a substring of a registry key.
      "google" -> contained in "google chrome" -> chrome.exe
      "command" -> contained in "command prompt" -> cmd.exe

    Tier 4 -- Key Contained In Input
      A registry key is a substring of the user's input.
      "open the chrome browser" -> "chrome" found inside -> chrome.exe

    No match -> helpful error listing all known apps.

  Works correctly: YES
  Tests passed:   12/12

--------------------------------------------------------------------------------
  FULL PIPELINE FLOW EXAMPLE (PHASE 2)
--------------------------------------------------------------------------------

  User types: "hey jarvis wanna hear blinding lights"

  Stage 1 -- Input Handler
    Input:  "hey jarvis wanna hear blinding lights"
    Output: "hey jarvis wanna hear blinding lights"  (already clean)

  Stage 2 -- Preprocessor
    Step 1 (greeting strip):
      "hey jarvis wanna hear blinding lights"
      -> "wanna hear blinding lights"

    Step 2 (contraction expand):
      "wanna hear" -> "want to hear"
      -> "want to hear blinding lights"

    Step 3 (polite prefix):
      No polite prefix found.
      -> "want to hear blinding lights"

    Output: "want to hear blinding lights"

  Stage 3 -- Intent Parser
    Scans for triggers in "want to hear blinding lights"
    Trigger "want to hear" found in PLAY_MEDIA list.
    Output: intent="PLAY_MEDIA", matched_trigger="want to hear"

  Stage 4 -- Entity Extractor
    Removes trigger "want to hear" from "want to hear blinding lights"
    Remainder: "blinding lights"
    Left filler check: no filler at start.
    Descriptor check: no "song called" pattern.
    Right filler check: no trailing filler.
    Output: entities={ "song_name": "blinding lights" }

  Stage 5 -- Action Executor
    Dispatches PLAY_MEDIA to media.play_media("blinding lights")
    Opens: https://www.youtube.com/search?q=blinding+lights
    Output: success=True, response="Playing 'blinding lights' on YouTube..."

  Final Command Object:
    raw_input   = "hey jarvis wanna hear blinding lights"
    clean_input = "want to hear blinding lights"
    intent      = "PLAY_MEDIA"
    entities    = { "song_name": "blinding lights" }
    success     = True
    response    = "Playing 'blinding lights' on YouTube..."

--------------------------------------------------------------------------------
  KNOWN LIMITATIONS (Phase 2)
--------------------------------------------------------------------------------

  - "wanna" needs a word after it to expand correctly.
    "wanna" alone does not resolve. ("wanna play kesariya" works fine.)

  - Fuzzy match uses simple string ops, not true edit-distance matching.
    "chormed" (2+ chars wrong) may not match "chrome".
    True fuzzy matching comes in Phase 3 via AI.

  - Descriptor pattern strips first-level descriptors only.
    "play a really good song called kesariya" -> "really good song called kesariya"
    The "really good" is not stripped (Phase 3 will handle this naturally).

  - Contraction expansion is one-to-one word replacement.
    Complex informal sentences still fail:
    "I feel bored, play something" -> UNKNOWN (Phase 3 handles this with AI)
