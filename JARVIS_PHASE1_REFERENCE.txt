--------------------------------------------------------------------------------
  MODULE DETAILS
--------------------------------------------------------------------------------

  [1] core/command.py
  -------------------
  What it is:
    A plain Python class that acts as a shared data container (the "baton")
    passed through every pipeline stage.

  Fields:
    raw_input    (str)   -- Exact string the user typed
    clean_input  (str)   -- After normalization (lowercase, stripped)
    intent       (str)   -- Classified intent (e.g. PLAY_MEDIA)
    entities     (dict)  -- Extracted slot data (e.g. {"song_name": "kesariya"})
    success      (bool)  -- Whether the action was performed successfully
    response     (str)   -- Human-readable message to display to user

  Intent Constants:
    INTENT_PLAY_MEDIA   = "PLAY_MEDIA"
    INTENT_OPEN_APP     = "OPEN_APP"
    INTENT_OPEN_WEBSITE = "OPEN_WEBSITE"
    INTENT_SEARCH_WEB   = "SEARCH_WEB"
    INTENT_UNKNOWN      = "UNKNOWN"

  Works correctly: YES
  Tested:         YES


  [2] config/intents.py
  ----------------------
  What it is:
    A pure data file. Contains INTENT_TRIGGERS dict mapping each intent
    to a list of trigger phrases. NO logic here, only data.

  Design rule:
    Longer trigger phrases come BEFORE shorter ones in each list.
    Reason: "play me" must be checked before "play" to avoid partial matches.

  Intents and trigger counts:
    PLAY_MEDIA   -- 11 triggers  (play, listen to, put on, i want to hear, ...)
    OPEN_APP     -- 11 triggers  (open, launch, start, can you open, ...)
    OPEN_WEBSITE --  6 triggers  (go to, visit, navigate to, ...)
    SEARCH_WEB   --  8 triggers  (search, look up, find, google, ...)

  Works correctly: YES
  Tested:         YES


  [3] config/apps.py
  -------------------
  What it is:
    Two registry dicts:
      APP_REGISTRY     -- maps app names to .exe paths on Windows 11
      WEBSITE_REGISTRY -- maps shorthand names to full URLs

  Current APP_REGISTRY entries:
    "chrome"        -> C:\Program Files\Google\Chrome\Application\chrome.exe
    "google chrome" -> C:\Program Files\Google\Chrome\Application\chrome.exe

  Current WEBSITE_REGISTRY entries:
    youtube, google, github, gmail, whatsapp, twitter, reddit, stackoverflow

  To add a new app:
    Add one line to APP_REGISTRY in config/apps.py. No other file changes needed.

  Works correctly: YES
  Tested:         YES


  [4] core/input_handler.py
  --------------------------
  What it is:
    Stage 1 of the pipeline. Cleans raw user input before parsing.

  What it does (in order):
    1. Strip leading/trailing whitespace
    2. Convert to lowercase
    3. Replace hyphens with spaces  ("vs-code" -> "vs code")
    4. Remove noise punctuation     (! ? . , etc.)
    5. Collapse multiple spaces to one
    6. Strip again

  Input/Output examples:
    "  Can you PLAY Kesariya!!  "  ->  "can you play kesariya"
    "Open VS-Code please."         ->  "open vs code please"
    "LAUNCH CHROME"                ->  "launch chrome"
    "   "                          ->  ""  (empty string)

  Works correctly: YES
  Tests passed:   8/8


  [5] core/intent_parser.py
  --------------------------
  What it is:
    Stage 2 of the pipeline. Classifies what the user wants to do.

  Algorithm:
    For each intent (in priority order):
      For each trigger phrase (longest to shortest):
        If trigger phrase found in clean_input:
          return (intent, matched_trigger)
    Return ("UNKNOWN", "")

  Intent priority order:
    1. PLAY_MEDIA    (checked first)
    2. OPEN_WEBSITE  (before OPEN_APP -- more specific)
    3. OPEN_APP
    4. SEARCH_WEB    (checked last)

  Why priority matters:
    "go to youtube" contains "open" but should be OPEN_WEBSITE, not OPEN_APP.
    Checking OPEN_WEBSITE first ensures the correct classification.

  Returns:
    A tuple: (intent_id, matched_trigger)
    matched_trigger is passed to entity_extractor to know what to strip.

  Input/Output examples:
    "play kesariya"              ->  ("PLAY_MEDIA", "play")
    "can you play kesariya"      ->  ("PLAY_MEDIA", "can you play")
    "open chrome"                ->  ("OPEN_APP", "open")
    "go to youtube"              ->  ("OPEN_WEBSITE", "go to")
    "search for python books"    ->  ("SEARCH_WEB", "search for")
    "hello there"                ->  ("UNKNOWN", "")

  Works correctly: YES
  Tests passed:   15/15


  [6] core/entity_extractor.py
  -----------------------------
  What it is:
    Stage 3 of the pipeline. Extracts WHAT the user is talking about.

  Algorithm ("Trigger Subtraction"):
    1. Find the matched_trigger in clean_input
    2. Take everything AFTER the trigger as the remainder
    3. Strip left-side filler words (a, the, some, up, me, my, for, ...)
    4. Strip right-side filler words (please, now, for me, ...)
    5. Map remainder to the correct entity key for the intent

  Entity keys per intent:
    PLAY_MEDIA   ->  {"song_name": "..."}
    OPEN_APP     ->  {"app_name": "..."}
    OPEN_WEBSITE ->  {"website": "..."}
    SEARCH_WEB   ->  {"query": "..."}

  Input/Output examples:
    intent=PLAY_MEDIA,   input="play kesariya",           trigger="play"
      -> {"song_name": "kesariya"}

    intent=PLAY_MEDIA,   input="play some relaxing music please", trigger="play"
      -> {"song_name": "relaxing music"}   (stripped "some" and "please")

    intent=OPEN_APP,     input="can you open chrome please", trigger="can you open"
      -> {"app_name": "chrome"}

    intent=OPEN_WEBSITE, input="go to youtube",           trigger="go to"
      -> {"website": "youtube"}

    intent=SEARCH_WEB,   input="search for python books", trigger="search for"
      -> {"query": "python books"}

  Works correctly: YES
  Tests passed:   16/16


  [7] core/pipeline.py
  ---------------------
  What it is:
    The orchestrator. The ONLY module that knows the order of operations.
    Calls each stage in sequence and passes the Command object forward.

  Execution stages:
    Stage 0: Create Command object with raw_input
    Stage 1: input_handler.handle()       -> fills clean_input
    Stage 2: intent_parser.parse()        -> fills intent
    Stage 3: entity_extractor.extract()   -> fills entities
    Stage 4: executor.execute()           -> fills success + response

  Guard clauses (short-circuits):
    - Empty input after normalization     -> "I didn't catch that..."
    - UNKNOWN intent                      -> "I'm not sure what you mean..."
    - Intent found but no entity          -> "Could you be more specific?"

  Key design: Executor is INJECTED (dependency injection).
    pipeline.set_executor(ActionExecutor())
    This means you can swap in a DryRunExecutor for testing without
    opening any real apps or browser tabs.

  Works correctly: YES
  Tested:         YES (all guard clauses verified)


  [8] actions/executor.py
  ------------------------
  What it is:
    The dispatcher. Reads intent from Command, calls the correct handler.

  Dispatch table:
    PLAY_MEDIA   ->  media.play_media(song_name)
    OPEN_APP     ->  apps.open_app(app_name)
    OPEN_WEBSITE ->  browser.open_website(website)
    SEARCH_WEB   ->  browser.search_web(query)

  Adding a new intent:
    1. Add intent constant to command.py
    2. Add trigger phrases to config/intents.py
    3. Create a handler file in actions/
    4. Add ONE line to the dispatch table in executor.py
    Nothing else changes.

  Works correctly: YES
  Tested:         YES


  [9] actions/media.py
  ---------------------
  What it is:
    Handles PLAY_MEDIA intent.

  How it works:
    Builds a YouTube search URL from song_name and opens it in the browser.
    URL format: https://www.youtube.com/search?q=<encoded_song_name>

  Example:
    play_media("kesariya")
    -> opens: https://www.youtube.com/search?q=kesariya
    -> returns: (True, "Playing 'kesariya' on YouTube...")

  Phase 3 upgrade:
    Replace webbrowser.open with Spotify/YouTube API call.
    The function signature stays identical.

  Works correctly: YES
  Tested:         YES (smoke test)


  [10] actions/browser.py
  ------------------------
  What it is:
    Handles OPEN_WEBSITE and SEARCH_WEB intents.

  open_website(website):
    1. Check WEBSITE_REGISTRY for shorthand (e.g. "youtube" -> full URL)
    2. If not found, try as raw URL if it contains a "."
    3. Else return helpful error message
    Example: open_website("youtube") -> opens https://www.youtube.com

  search_web(query):
    Builds Google search URL and opens it.
    URL format: https://www.google.com/search?q=<encoded_query>
    Example: search_web("python books") -> opens Google search results

  Works correctly: YES
  Tested:         YES (smoke test)


  [11] actions/apps.py
  ---------------------
  What it is:
    Handles OPEN_APP intent using subprocess.Popen.

  How it works:
    1. Look up app_name in APP_REGISTRY (config/apps.py)
    2. Validate the .exe path exists
    3. Launch with subprocess.Popen (non-blocking -- assistant keeps running)
    4. If not found, list known apps in the error message

  Example:
    open_app("chrome")
    -> subprocess.Popen(["C:\...\chrome.exe"])
    -> returns: (True, "Opening Chrome...")

  Works correctly: YES
  Tested:         YES (path validation tested)


  [12] main.py
  -------------
  What it is:
    Entry point. Infinite REPL loop.

  Flow:
    1. Print banner
    2. Build pipeline with real ActionExecutor
    3. Loop:
       a. input("  You: ")
       b. Check if exit command -> break
       c. pipeline.process(raw_input)
       d. print response
    4. On Ctrl+C: graceful shutdown message

  Exit commands: exit, quit, q, bye, shutdown

  Works correctly: YES


--------------------------------------------------------------------------------
  FULL PIPELINE FLOW (EXAMPLE)
--------------------------------------------------------------------------------

  User types: "can you play kesariya"

  Step 1 -- Input Handler
    Input:   "can you play kesariya"
    Output:  "can you play kesariya"   (already clean in this case)

  Step 2 -- Intent Parser
    Scans trigger phrases for each intent.
    "can you play" found in PLAY_MEDIA triggers.
    Output:  intent="PLAY_MEDIA", matched_trigger="can you play"

  Step 3 -- Entity Extractor
    Removes "can you play" from "can you play kesariya"
    Remainder: "kesariya"
    No filler words to strip.
    Output:  entities={"song_name": "kesariya"}

  Step 4 -- Command Object state
    raw_input   = "can you play kesariya"
    clean_input = "can you play kesariya"
    intent      = "PLAY_MEDIA"
    entities    = {"song_name": "kesariya"}

  Step 5 -- Action Executor
    intent=PLAY_MEDIA -> calls media.play_media("kesariya")
    Opens: https://www.youtube.com/search?q=kesariya
    Output:  success=True, response="Playing 'kesariya' on YouTube..."

  Step 6 -- Response Layer (main.py)
    Prints: [OK] JARVIS: Playing 'kesariya' on YouTube...

--------------------------------------------------------------------------------
  KNOWN LIMITATIONS (Phase 1)
--------------------------------------------------------------------------------

  - Only Chrome is in APP_REGISTRY. Add more apps manually in config/apps.py.
  - No voice input. Text only.
  - No memory. Each command is independent.
  - Cannot handle ambiguous multi-intent input.
    Example: "open chrome and search python" -> only first intent fires.
  - Song names with filler-like words may be trimmed incorrectly.
    Example: "play a song by the weeknd" -> song_name="song by weeknd"
             (strips "a" and "the")
    Fix in Phase 2 by using smarter entity boundary detection.
