--------------------------------------------------------------------------------
  THE PIPELINE: PHASE 2 vs PHASE 3
--------------------------------------------------------------------------------

  PHASE 2 PIPELINE (5 stages):
    raw input
      -> [Input Handler]      normalize text
      -> [Preprocessor]       rewrite informal language
      -> [Intent Parser]      classify intent with rules
      -> [Entity Extractor]   extract entity with rules
      -> [Action Executor]    perform action

  PHASE 3 PIPELINE -- AI PATH (3 stages):
    raw input
      -> [Input Handler]      normalize text
      -> [AI Parser]          LLM classifies intent AND extracts entity
      -> [Action Executor]    perform action

  PHASE 3 PIPELINE -- FALLBACK PATH (if AI fails or unavailable):
    raw input
      -> [Input Handler]      normalize text
      -> [Preprocessor]       Phase 2 rules
      -> [Intent Parser]      Phase 2 rules
      -> [Entity Extractor]   Phase 2 rules
      -> [Action Executor]    perform action

  The switch between AI path and fallback is AUTOMATIC.
  The user never sees the difference.
  The Action Executor is completely unchanged in both paths.

  [3] core/ai_parser.py  (NEW)
  ------------------------------
  What it is:
    The core Phase 3 module. Sends user input to Groq LLM and returns
    (intent, entities) in the same format as Phase 2 parsers.

  AI Model:
    llama-3.3-70b-versatile via Groq API
    - Free tier: 14,400 requests per day
    - Very fast inference (usually under 1 second)
    - Highly capable at intent understanding

  How it works:
    1. Loads GROQ_API_KEY from .env
    2. Sends a carefully engineered system prompt + user input to the LLM
    3. LLM returns structured JSON:
         { "intent": "PLAY_MEDIA",
           "entities": { "song_name": "upbeat music" },
           "confidence": "high" }
    4. JSON is parsed and returned as (intent, entities)
    5. On any failure: returns (INTENT_UNKNOWN, {}) for graceful fallback

  The System Prompt (key design):
    - Defines all 4 intents and their entity keys
    - Instructs the LLM to return ONLY JSON (no explanation)
    - Gives examples of mood-to-action mapping:
        "i'm bored"      -> PLAY_MEDIA, song_name="upbeat music"
        "i feel stressed" -> PLAY_MEDIA, song_name="calming music"
        "i need to code" -> OPEN_APP,   app_name="vs code"
    - Sets temperature=0.1 for deterministic, reliable output

  Error handling:
    - JSONDecodeError  -> logs warning, returns (UNKNOWN, {})
    - Network error    -> logs warning, returns (UNKNOWN, {})
    - Invalid intent   -> logs warning, returns (UNKNOWN, {})
    All errors trigger fallback to Phase 2 rules -- system never crashes.

  is_available() function:
    Returns True if GROQ_API_KEY is set in environment.
    Called once at pipeline startup to decide which path to use.

  Works correctly: YES
  Tested:         YES (15 diverse inputs, all correct)


  [4] core/pipeline.py  (UPDATED)
  ----------------------------------
  What changed:
    Added ai_parser import.
    Added _parse_with_ai() method.
    Added _parse_with_rules() method (Phase 2 pipeline encapsulated).
    Main process() now tries AI first, falls back to rules automatically.
    Shows [AI] status line at startup.

  Logic in process():
    if AI is available:
      try _parse_with_ai()
      if AI returns UNKNOWN or empty entities:
        use _parse_with_rules() instead
    else:
      use _parse_with_rules()

  _parse_with_ai():
    Calls ai_parser.parse(clean_input)
    Returns (cmd, True) on success, (cmd, False) to signal fallback needed.

  _parse_with_rules():
    Runs the full Phase 2 pipeline (preprocessor -> intent -> entity).
    Returns cmd with response set if any guard fires.

  Works correctly: YES
  Tested:         YES (full end-to-end)


--------------------------------------------------------------------------------
  FULL PIPELINE FLOW EXAMPLE (PHASE 3 -- AI PATH)
--------------------------------------------------------------------------------

  User types: "i'm bored, play something fun"

  Stage 1 -- Input Handler
    Input:  "i'm bored, play something fun"
    Output: "im bored play something fun"  (lowercased, punctuation stripped)

  Stage 2 -- AI Parser
    Sends to Groq API:
      System: [intent classification system prompt]
      User:   "im bored play something fun"

    LLM returns:
      { "intent": "PLAY_MEDIA",
        "entities": { "song_name": "upbeat music" },
        "confidence": "high" }

    Parsed:
      cmd.intent   = "PLAY_MEDIA"
      cmd.entities = { "song_name": "upbeat music" }

  Stage 3 -- Action Executor
    Dispatches PLAY_MEDIA to media.play_media("upbeat music")
    Opens: https://www.youtube.com/search?q=upbeat+music
    Output: success=True, response="Playing 'upbeat music' on YouTube..."

  Final Command Object:
    raw_input   = "i'm bored, play something fun"
    clean_input = "im bored play something fun"
    intent      = "PLAY_MEDIA"
    entities    = { "song_name": "upbeat music" }
    success     = True
    response    = "Playing 'upbeat music' on YouTube..."


--------------------------------------------------------------------------------
  FULL PIPELINE FLOW EXAMPLE (PHASE 3 -- FALLBACK PATH)
--------------------------------------------------------------------------------

  Scenario: Network is down, AI call fails.

  User types: "play kesariya"

  Stage 1 -- Input Handler
    Output: "play kesariya"

  Stage 2 -- AI Parser
    API call fails (network error / timeout)
    Logs warning, returns (INTENT_UNKNOWN, {})
    Pipeline detects UNKNOWN -> triggers fallback

  Stage 2b -- Fallback (Phase 2 rules)
    Preprocessor:   "play kesariya" (no change needed)
    Intent Parser:  trigger "play" found -> PLAY_MEDIA
    Entity Extract: "kesariya"

  Stage 3 -- Action Executor
    Plays "kesariya" on YouTube as normal.

  User sees NO DIFFERENCE. The fallback is invisible.

--------------------------------------------------------------------------------
  KNOWN LIMITATIONS (Phase 3)
--------------------------------------------------------------------------------

  - Requires internet connection for AI path.
    (Falls back to Phase 2 rules offline -- still functional.)

  - API key has daily limits (14,400 requests/day on free tier).
    For personal use this is more than enough.

  - AI response adds ~1 second latency per command.
    Phase 2 rules respond instantly.

  - "vs code" is returned by AI but not in APP_REGISTRY yet.
    Fix: uncomment VS Code in config/apps.py and set the correct path.

  - AI may occasionally return wrong intent for very ambiguous input.
    Example: "open something" may return OPEN_APP or OPEN_WEBSITE randomly.
    Phase 4 will add a clarification dialog for ambiguous commands.
